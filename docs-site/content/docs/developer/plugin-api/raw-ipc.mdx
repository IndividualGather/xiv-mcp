For plugins that do not use `XivMcpClient.cs`.

- XIV MCP's gates are named `XivMcp.<Gate>`. Yours are named `<InternalName>.XivMcp.<Gate>`.
- XIV MCP's gates reply with `{"ok": true, …}` or `{"ok": false, "error": "…"}` and never throw into your plugin.
- `owner` is your `IDalamudPluginInterface.InternalName`. Registering from your constructor is fine.

## Gates XIV MCP provides

| Gate | Signature | Returns / does |
|---|---|---|
| `ApiVersion` | `Func<int>{:csharp}` | `2` |
| `IsReady` | `Func<bool>{:csharp}` | True while loaded |
| `ListCapabilities` | `Func<string>{:csharp}` | `{"capabilities":[{"id","risk","title","description","default"}]}{:json}` |
| `RegisterTool` | `Func<string owner, string definitionJson, string>{:csharp}` | `{"name","enabled","awaitingConsent","state","capabilities":[{"id","mode"}]}{:json}` |
| `UnregisterTool` | `Func<string owner, string name, string>{:csharp}` | `{"removed": bool}{:json}` |
| `UnregisterAll` | `Func<string owner, string>{:csharp}` | `{"removed": count}{:json}` |
| `GetStatus` | `Func<string owner, string>{:csharp}` | `{"state","canRun","suspendReason","tools":[{"name","mode","own"}],"capabilities":[{"id","mode"}],"dependencies":[…]}{:json}` |
| `DeclareDependencies` | `Func<string owner, string json, string>{:csharp}` | Declares the tools your jobs use (see below); returns `{"dependencies":[…]}` |
| `CheckPermission` | `Func<string owner, string capability, string>{:csharp}` | `{"mode":"allow"\|"ask"\|"deny","enabled","suspended","state"}{:json}` |
| `RequestApproval` | `Func<string callId, string requestJson, string>{:csharp}` | Request `{"capability","summary"}`; returns `{"approvalId","state"}` |
| `GetApproval` | `Func<string approvalId, string>{:csharp}` | `{"state":"pending"\|"approved"\|"denied"}{:json}` |
| `CompleteCall` | `Func<string callId, string resultJson, string>{:csharp}` | Finishes a pending call |
| `FailCall` | `Func<string callId, string message, string>{:csharp}` | Fails a pending call |
| `ReportProgress` | `Func<string callId, string text, string>{:csharp}` | Adds a job log line |
| `StartJob` | `Func<string owner, string jobJson, string>{:csharp}` | Job `{"name","steps":[{"id","tool","args","note"}]}`; returns `{"job":{…}}` |
| `GetJob` | `Func<string id, string>{:csharp}` | `{"job"}` |
| `ListJobs` | `Func<string owner, string>{:csharp}` | `{"jobs"}`: the jobs your plugin started |
| `PauseJob` / `ResumeJob` / `CancelJob` | `Func<string id, string>{:csharp}` | Job control |
| `Ready` / `Disposing` | messages | Register on `Ready`; stop running calls on `Disposing` |

`state` is one of `undecided`, `kept_disabled`, `enabled`, `awaiting_consent` or `suspended`.

## Tool definition

```json
{
  "name": "myplugin_restock",
  "description": "Buys what your list is short of from the nearest vendor.",
  "inputSchema": { "type": "object", "properties": {} },
  "readOnly": false,
  "destructive": false,
  "capabilities": ["move_character", "game_ui", "spend_gil"]
}
```

`capabilities` is required unless `readOnly`. `readOnly` and `destructive` cannot both be true, and unknown capability ids are rejected.

### Dependencies

The declaration replaces the previous one; `{"tools": []}` clears it.

```json
{
  "tools": [
    { "tool": "navigate_to" },
    {
      "tool": "otherplugin_announce",
      "plugin": "OtherPlugin",
      "name": "Other Plugin",
      "repo": "https://example.com/repo.json",
      "minVersion": "1.2.0"
    }
  ]
}
```

A built-in tool is named alone; naming a plugin for one is refused. Any other tool needs `plugin`, `name`, `repo` (an `https://` URL, or `"official"`) and `minVersion`. At most 64 tools.

Each entry of `dependencies` in the reply and in `GetStatus`:

```json
{
  "tool": "navigate_to",
  "plugin": null,
  "state": "ok",
  "message": "Ready. Without vnavmesh: XIV MCP puts a flag on …",
  "install": [
    {
      "plugin": "vnavmesh", "name": "vnavmesh",
      "repo": "https://puni.sh/api/repository/veyn",
      "needed": false, "installed": false, "outdated": false,
      "reason": "Walks there for you.",
      "without": "XIV MCP puts a flag on your map and waits …"
    }
  ]
}
```

`state` is one of the [dependency states](/docs/developer/plugin-api/reference#mcpdependencystatus). `install` lists the plugins to install, enable or update. `needed: true` is a plugin an integration tool cannot run without (`state` is then `needs_plugin`); `needed: false` is one an XIV MCP core tool can use, with `without` saying what XIV MCP does instead.

## Gates your plugin provides

| Gate | Signature | Does |
|---|---|---|
| `<InternalName>.XivMcp.Invoke` | `Func<string callId, string tool, string argsJson, string>{:csharp}` | Runs a tool on the framework thread, after the permission checks. Reply with `{"result": …}`, `{"error": "…"}` or `{"pending": true}`; finish a pending call with `CompleteCall` / `FailCall`. |
| `<InternalName>.XivMcp.Cancel` | `Action<string callId>{:csharp}` | Optional: stop a pending call. |

`CompleteCall` and `RequestApproval` may be called from inside `Invoke`, before you reply.

## A call that takes a minute

<Mermaid
  caption="A long-running call over raw IPC. The approval and the cancel only happen when they are needed."
  chart={`sequenceDiagram
  participant X as XIV MCP
  participant Y as Your plugin
  X->>Y: Invoke("c1", "myplugin_farm", args)
  Y-->>X: {"pending": true}
  Note over Y: start the work, return at once
  loop any number of times
    Y->>X: ReportProgress("c1", "12 kills")
  end
  opt at the risky moment
    Y->>X: RequestApproval("c1", capability and summary)
    X-->>Y: approvalId a7, pending
    loop every 250 ms
      Y->>X: GetApproval("a7")
      X-->>Y: pending, then approved or denied
    end
  end
  opt the job is paused or cancelled, or the app gives up
    X->>Y: Cancel("c1")
    Note over Y: stop safely
  end
  alt done
    Y->>X: CompleteCall("c1", result)
  else failed
    Y->>X: FailCall("c1", "Bags full after 31 kills.")
  end`}
/>

`CompleteCall` takes the result itself, not wrapped in `{"result": …}`. The approval request is `{"capability": "spend_gil", "summary": "Repair for 3,200 gil"}`.

XIV MCP sets no time limit of its own on pending calls. When an AI app calls your tool directly, the app's own [time limit](/docs/developer/plugin-api/time-limits) applies, often a minute; when it gives up, you get `Cancel`. Approval windows decline after two minutes, and after a `Cancel` XIV MCP waits up to two minutes for your `CompleteCall` or `FailCall`.
