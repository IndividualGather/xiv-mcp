These tools act in the game, so they need **Game & navigation** changes to be allowed (or set to *Ask*) in `/xivmcp` → **Modules**.

## Windows and menus

| Tool | What it does |
|---|---|
| `list_windows` / `open_window` / `close_window` | Opens main menu windows (Achievements, Saddlebag, Currency and more); `close_window` closes any open window by name |
| `interact_with_object` | Targets and interacts with a nearby object or NPC, like clicking it: a summoning bell, the company chest, the voyage panel. When furniture blocks the view, it tries again without the line-of-sight check, then from right next to the object. |
| `get_menu` / `select_menu_option` | The choice menu or Yes/No question the game shows after an interaction; picks an entry, answers Yes or No, or advances dialogue |
| `recover_game_state` | Gets your character out of a conversation, menu, turn-in or shop window that was left open, or out of a conversation the game still holds after its window vanished: clicks through dialogue, answers No, leaves menus, closes the windows that are shown (never hidden ones) and, as a last resort, presses Escape a few times. Never acts in combat, cutscenes or while loading. |
| `load_game_data` | Asks the game to send your achievements or titles without opening their window |

Windows that act instead of opening something (Log Out, Exit Game, Return, Ready Check, Countdown, Stance) cannot be triggered through `open_window`.

## Walking and travel

| Tool | What it does |
|---|---|
| `navigate_to` | Gets you to a summoning bell, the company chest (in the FC house, or in its workshop if it stands there), the workshop, an inn, your house or apartment, a named object or NPC (with `zone` to pick between NPCs of the same name), or a fishing spot (as a Fisher, it walks to the water's edge, facing the water, until you can cast). It walks and travels for you when a navigation plugin is installed, and shows you the way otherwise (see below). |
| `get_navigation_status` / `stop_navigation` | What is installed and moving; an immediate stop |
| `get_automation_status` | What XIV MCP detected about AutoRetainer, YesAlready and TextAdvance, and what it is pausing |

Teleports cost gil. For flags on the map and routes through several spots, see [Maps and routes](/docs/user/features/maps-and-routes).

### With or without navigation plugins

Moving works without any other plugin. When a part of the way is something XIV MCP cannot do itself, it asks you to do it, and waits until you have. You see the request in chat and as a notification, and the game's taskbar button flashes.

The walking plugin is **vnavmesh**, the travel plugin **Lifestream**. Where to get them is on [Plugins XIV MCP uses](/docs/user/plugins#where-to-get-them).

| Part of the way | With a plugin | Without one |
|---|---|---|
| Walking in the zone (vnavmesh) | Walks you there | Puts the flag on your map and asks you to walk to it |
| Teleporting to another zone (Lifestream) | Teleports you | Names the aetheryte (and the aethernet shard), opens the map at it, and asks you to teleport |
| The aethernet of the Firmament and the Cosmic Exploration zones (Lifestream; Cosmic Exploration not tried in game yet) | Takes the aethernet once you are at the shard | Asks you to use the shard (without a walking plugin, it puts the flag on the shard first) |
| Inn room, house, apartment, workshop (Lifestream) | Takes you inside | Asks you to go in |
| Another world (Lifestream) | Travels there | Asks you to use World Visit or Data Center Travel |

From an inn room, XIV MCP first teleports you out with the game's own teleport (to the city's aetheryte when the target is an aethernet shard), then Lifestream takes over.

XIV MCP knows where most aetherytes and aethernet shards stand from the zone's own layout (the rest from game data and map markers), and picks the one nearest the NPC among those you have attuned to (an aethernet shard in another city also needs that city's aetheryte, since the trip goes through it). If you can use none of them, it says so instead of trying (in the NPC's own zone, it walks). NPC positions come from the map, which has no height, so it compares distances on the ground, and the nearest shard can be on a level the NPC cannot be walked to from (Limsa's Airship Landing is reached only by lift). When the walk from there runs into an obstacle, XIV MCP travels once more, by another shard or aetheryte. Some shard names exist in more than one city (Limsa and Gridania both have an Airship Landing); for those, XIV MCP teleports to the right city first and takes the aethernet from there.

Many NPC names stand in several places: a quest puts copies of an NPC where its story happens, and those only show while the quest asks for them. For an NPC by name, XIV MCP goes to the one that stands there for good (it does more than quests: talks, sells, plays Triple Triad), and of those to the one nearest you (in your zone, then in your area, such as Ishgard). When two NPCs of the same name both stand there for good (there is a House Fortemps guard in the Pillars and one in Coerthas), give `zone` with part of the zone's or area's name ("Pillars") to pick one.

Right after a teleport, vnavmesh can take a moment to load the new zone's navmesh, and a walk asked for too early never starts. XIV MCP then waits for the navmesh and asks again, up to three times.

### Zones with their own aethernet

The Firmament and the Cosmic Exploration zones (Sinus Ardorum, Phaenna, Oizys and Auxesia) have aethernet shards that the game's aetheryte list does not include. Travel with them has been tried in the Firmament; in the Cosmic Exploration zones it should work the same way, but it has not been tried in game yet. XIV MCP reads them from the game data the first time it needs one of these zones: where each shard stands and the name its menu lists it by. None of this is written into XIV MCP itself, so shards that a patch adds or moves are picked up.

Inside such a zone, XIV MCP takes the aethernet when walking to the nearest shard, and on from the shard nearest the target, is clearly shorter than walking straight there. It walks you to the first shard and the travel plugin picks the destination in the shard's menu. Without a travel plugin, XIV MCP asks you to use the shard and waits until you are at the destination (or have walked on); without a walking plugin either, it puts the flag on the shard first. If the trip does not happen, XIV MCP walks instead and says so in the steps. When the shard's menu opened without the destination (you have not attuned to it yet, for example), it also leaves that destination out of later trips until XIV MCP restarts.

The Firmament is reached from the Foundation: XIV MCP teleports you to the Foundation aetheryte (teleports cost gil) and uses its menu to travel to the Firmament. It opens with the quest "Towards the Firmament". The Cosmic Exploration zones are entered from Bestways Burrow; go there first, and XIV MCP should then travel within them (not tried in game yet).

Eureka, the Bozjan Southern Front, Zadnor and the Occult Crescent have shards of their own too, and XIV MCP finds them the same way. But these field operations count as duties, and `navigate_to` does not move you while you are in a duty.

### Zones entered through a door

Some zones have no aetheryte at all: you enter them by talking to someone in another zone, who asks "Enter Fortemps Manor?" (the House Fortemps guard in the Pillars), or by using an object there. XIV MCP reads these doors from the game data the first time it needs one: which NPC or object leads into which zone, where it stands, and what it asks of you (quests, a level, a fee). It then travels to the door like to any NPC, talks to it, answers Yes to its question, and goes on inside.

Before setting off, it checks that the door will let you in: a door that needs a quest you have not finished, a higher level or more gil is not tried, and XIV MCP says what is missing. Some doors decide by themselves who may enter (the Sanctum of the Twelve's, for one, only lets in a booked wedding); when such a door offers no way in, XIV MCP closes its menu and says so. A question other than the door's own is left for you to answer. Where several doors lead into the same zone from one spot (one for each part of the story, of which the game shows one), it uses whichever stands there. Inn rooms and housing districts are not entered this way: `navigate_to` has destinations of their own for those.

Doors that are objects instead of people (in Mare Lamentorum, Elpis and Living Memory) are found the same way, but have not been tried in game yet.

### Riding

For a walk of 50 yalms or more, XIV MCP gets on a mount first (Mount Roulette), and flies where the zone allows it and you have found its aether currents. It gets off when you arrive. Turn this off in `/xivmcp` → Modules → Game & navigation → *Ride a mount for longer walks*.

The same applies to tools that take you somewhere on the way, such as `buy_item` and `turn_in_collectables`. The wait ends when you arrive, when you stop it with `stop_navigation`, or after the timeout (10 minutes by default). If you do not arrive in time, your assistant is told you did not get there, and why. Which plugins can do which part is listed on [Plugins XIV MCP uses](/docs/user/plugins).

## Characters, worlds and jobs

| Tool | What it does |
|---|---|
| `list_characters` | The characters XIV MCP has seen (in the lobby lists and in the game): worlds, data center, service account, and whether each is on the account in use |
| `switch_character` | Logs out and into another character of the account, on any world, data center and service account, and waits until it is in the game. After a lost connection (error 90002 and the like) it presses OK and logs back in; other lobby errors, such as maintenance, stop it |
| `refresh_character_list` | Logs out and straight back in, so XIV MCP learns this data center's character list |
| `visit_world` | World visit or data center travel for the current character. A travel plugin travels for you (if it stops without getting there, for example with the aetheryte's menu left open, XIV MCP closes the menu and asks it again, up to three times); without one, XIV MCP asks you to use World Visit or Data Center Travel and waits until you arrive. |
| `switch_gearset` | Changes job by equipping a gear set, by number, name or job (the set with the highest item level of that job). When an item of the set is missing and the game offers a replacement, it answers Yes (or No with `replace_missing: false`). It returns once the job has changed and the set's pieces are on |
| `leave_duty` | Leaves the current duty like the Duty Finder's Leave entry, once the current fight is over |
| `abandon_quest` | Abandons an accepted quest, like the journal's Abandon button. Its progress is lost, and a daily quest's allowance is not given back |

Logging in is built in. XIV MCP goes through the game's own lobby (title screen, data center, service account, character list) and confirms only when the game's prompt names the right character. It remembers each character's service account (one Square Enix account can hold several service accounts, each a separate licence with its own characters). Accounts are told apart by what XIV MCP observes, so it never tries to reach a character of another account. When the game opens at the character list of another data center (the one a character was visiting), XIV MCP goes back to the title screen and chooses the right one. Right after the login, the game can still report the previous character for a few seconds, so XIV MCP waits that out. Only if another character stays in game does it log out, and then it logs in again from the title screen. The switch reports done once the character stands in the world, after the zone has loaded, so the next step can start right away.
