These tools act in the game, so they need **Game & navigation** changes to be allowed (or set to *Ask*) in `/xivmcp` → **Modules**.

## Windows and menus

| Tool | What it does |
|---|---|
| `list_windows` / `open_window` / `close_window` | Opens main menu windows (Achievements, Saddlebag, Currency and more); `close_window` closes any open window by name |
| `interact_with_object` | Targets and interacts with a nearby object or NPC, like clicking it: a summoning bell, the company chest, the voyage panel. When furniture blocks the view, it tries again without the line-of-sight check, then from right next to the object. |
| `get_menu` / `select_menu_option` | The choice menu the game shows after an interaction; picks an entry or advances dialogue |
| `recover_game_state` | Gets your character out of a conversation, menu, turn-in or shop window that was left open, or out of a conversation the game still holds after its window vanished: clicks through dialogue, answers No, leaves menus, closes the windows that are shown (never hidden ones) and, as a last resort, presses Escape a few times. Never acts in combat, cutscenes or while loading. |
| `load_game_data` | Asks the game to send your achievements or titles without opening their window |

Windows that act instead of opening something (Log Out, Exit Game, Return, Ready Check, Countdown, Stance) cannot be triggered through `open_window`.

## Walking and travel

| Tool | What it does |
|---|---|
| `navigate_to` | Gets you to a summoning bell, the company chest, the workshop, an inn, your house or apartment, a named object or NPC, or a fishing spot (as a Fisher, it walks to the water's edge, facing the water, until you can cast). It walks and travels for you when a navigation plugin is installed, and shows you the way otherwise (see below). |
| `get_navigation_status` / `stop_navigation` | What is installed and moving; an immediate stop |
| `get_automation_status` | What XIV MCP detected about AutoRetainer, YesAlready and TextAdvance, and what it is pausing |

Teleports cost gil. For flags on the map and routes through several spots, see [Maps and routes](/docs/user/features/maps-and-routes).

### With or without navigation plugins

Moving works without any other plugin. When a part of the way is something XIV MCP cannot do itself, it asks you to do it, and waits until you have. You see the request in chat and as a notification, and the game's taskbar button flashes.

The walking plugin is **vnavmesh**, the travel plugin **Lifestream**. Where to get them is on [Plugins XIV MCP uses](/docs/user/plugins#where-to-get-them).

| Part of the way | With a plugin | Without one |
|---|---|---|
| Walking in the zone (vnavmesh) | Walks you there | Puts the flag on your map and asks you to walk to it |
| Teleporting to another zone (Lifestream) | Teleports you | Names the aetheryte (and the aethernet shard), opens the map at it, and asks you to teleport |
| Inn room, house, apartment, workshop (Lifestream) | Takes you inside | Asks you to go in |
| Another world (Lifestream) | Travels there | Asks you to use World Visit or Data Center Travel |

### Riding

For a walk of 50 yalms or more, XIV MCP gets on a mount first (Mount Roulette), and flies where the zone allows it and you have found its aether currents. It gets off when you arrive. Turn this off in `/xivmcp` → Modules → Game & navigation → *Ride a mount for longer walks*.

The same applies to tools that take you somewhere on the way, such as `buy_item` and `turn_in_collectables`. The wait ends when you arrive, when you stop it with `stop_navigation`, or after the timeout (10 minutes by default). If you do not arrive in time, your assistant is told you did not get there, and why. Which plugins can do which part is listed on [Plugins XIV MCP uses](/docs/user/plugins).

## Characters, worlds and jobs

| Tool | What it does |
|---|---|
| `list_characters` | The characters XIV MCP has seen (in the lobby lists and in the game): worlds, data center, service account, and whether each is on the account in use |
| `switch_character` | Logs out and into another character of the account, on any world, data center and service account, and waits until it is in the game |
| `refresh_character_list` | Logs out and straight back in, so XIV MCP learns this data center's character list |
| `visit_world` | World visit or data center travel for the current character. A travel plugin travels for you; without one, XIV MCP asks you to use World Visit or Data Center Travel and waits until you arrive. |
| `switch_gearset` | Changes job by equipping a gear set, by number, name or job (the set with the highest item level of that job) |
| `leave_duty` | Leaves the current duty like the Duty Finder's Leave entry, once the current fight is over |
| `abandon_quest` | Abandons an accepted quest, like the journal's Abandon button. Its progress is lost, and a daily quest's allowance is not given back |

Logging in is built in. XIV MCP goes through the game's own lobby (title screen, data center, service account, character list) and confirms only when the game's prompt names the right character. It remembers each character's service account (one Square Enix account can hold several service accounts, each a separate licence with its own characters). Accounts are told apart by what XIV MCP observes, so it never tries to reach a character of another account.
